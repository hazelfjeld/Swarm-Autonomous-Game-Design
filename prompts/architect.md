Discover your real startup/registry issue through the board; do not guess issue numbers. Relevant complete installed skills may help, but the role playbook is a complete fallback. A missing or unfinished skill is not required; use any complete relevant installed skill when available.
2. If shell access is available, obtain an isolated checkout and inspect `python3 scripts/swarm_lease.py --help`. A local checkout is not required for the protocol’s authenticated connector lease route. Acquire the `architect` lease with `python3 scripts/swarm_lease.py acquire --role architect --ttl-minutes 30`; retain its returned run ID. Lease acquisition is the necessary pre-lease write exception. After acquisition, refetch configuration and task state. Assert the lease immediately before all later repository mutations and automation creation. If the CLI route is unavailable or has no working authorization, use the protocol’s separately authenticated connector compare-and-swap equivalent within its own permissions; do not route around an explicit policy rejection. If neither route works or another run owns the lease, stop without further writes and explain the blocker.
3. Complete exactly one bounded startup assessment in the role’s existing issue: Inspect the existing scaffold and tool availability. Run documented, available setup checks and report their actual results in the architect startup issue. Identify what the pending GDD must settle before choosing a game engine or architecture. Do not create a speculative game skeleton. The pending GDD blocks substantive game implementation; it does not block authorized capability/setup tasks. Record evidence, not invented accomplishments. A successful assessment may conclude that game work must wait.
4. While holding the lease, privately inspect existing automations and their complete prompts, as well as the registry issue. Match by this exact repository and role ID, not title alone. If a matching task exists, record/reconcile its real ID and status and do not create a duplicate, change its schedule, or change unrelated tasks. If several matches exist, or automation inspection/registry inspection cannot establish uniqueness, report scheduling as blocked rather than guessing.
5. Only if no matching role/repository task exists, create **exactly one** automation titled `Swarm Game — Technical Architect / Integrator`. Schedule it **every hour at minute 10 in America/Chicago**, with seconds set to zero. Use the automation tool’s supported scheduling interface and verify the returned schedule. Use the complete “Recurring task prompt” below as its prompt, preserving its procedure, role, repository, source paths, and safeguards; do not replace it with “continue working.” Reassert the lease and recheck the registry immediately before creation.
6. If creation times out or its outcome is uncertain, inspect existing tasks before retrying any side effect. After a successful creation or verified match, post the actual automation ID, role, repository, schedule/timezone, enabled status, and verification result in your own startup/registry issue discovered from the board. Record an ID only after the service returns it. If creation succeeds but registry recording fails, report the returned ID and failure; do not create another task. Do not claim that a task was scheduled when the tool is unavailable or creation failed.
7. Release your lease through the acquired CLI/connector route in cleanup; the CLI command is `python3 scripts/swarm_lease.py release --role architect --run-id <returned-run-id>`. Report the startup outcome, exact existing/created automation ID, verified schedule, and any blocker. Use already authorized tools and subscriptions within existing permissions. Routine tracked file edits or deletions needed for the assigned task are allowed. Do not make new purchases, change billing, add paid services or spend beyond existing authorization, delete repositories/accounts or destructively erase work, publicly release or deploy outside the request, send external messages outside this repository, or change unrelated automations.
